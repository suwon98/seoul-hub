# 보안 점검과 계정 기능 검증

최종 점검일: 2026-10-19. 코드·자동 테스트와 운영 계정 흐름을 확인했다. 화면과 메일 수신 검증에는 사용자 확인 결과가 포함된다. 침투 테스트나 보안 전수 감사를 의미하지 않는다.

## 현재 구현

- 이메일만으로 가입 요청을 접수합니다. 비밀번호는 이메일 소유자가 60분짜리 일회용 인증 링크를 통해 처음 설정합니다. 인증 전 로그인 불가, 기존 회원도 인증 필요. 가입 요청자가 다른 사람의 메일로 임의 비밀번호를 미리 정하는 상황을 방지합니다.
- 비밀번호 재설정 링크는 20분, 256비트 난수입니다. DB에는 SHA-256 해시만 저장하며 용도(인증/재설정)를 구분합니다. 만료·재사용·다른 용도 사용을 거부합니다. 계정 행 잠금과 원자적 토큰 소비로 동시에 요청해도 한 번만 처리합니다.
- GET으로 링크를 여는 것만으로 변경하지 않습니다. 사용자가 폼을 제출해야 완료됩니다. 링크 토큰은 URL fragment `#token=`에 넣어 HTTP 접근 로그/Referer로 보내지 않으며 완료 시 주소에서 제거합니다. Referrer-Policy는 no-referrer입니다.
- 재설정 후 모든 DB 로그인 세션을 삭제합니다. 자동 로그인하지 않으며 새 비밀번호로 다시 로그인해야 합니다. 인증 완료 역시 기존 세션/계정 토큰을 종료합니다.
- 탈퇴는 인증된 세션, 현재 비밀번호, 정확한 `회원 탈퇴` 문구를 요구합니다. 활성 DB에서 계정·본인 질문/답변·본인 질문의 답변·토큰·세션을 한 트랜잭션으로 삭제합니다. UI에 삭제 범위를 표시하고 다른 회원의 질문/독립 답변은 유지합니다.
- 메일 요청은 이메일당 15분 3회, 인스턴스 전체 15분 40회 제한입니다. 같은 계정/용도 재발급 시 이전 링크를 무효화합니다. 가입·재발송·복구의 정상 접수 응답은 가입 상태/제한/발송 실패를 직접 드러내지 않는 공통 문구입니다. 기존 이메일 중복 확인 API는 제거했습니다.
- 운영은 Brevo HTTPS API, 고정된 제공업체 주소, 연결/요청 타임아웃을 사용합니다. API 키·수신자·본문·원본 오류를 로그에 남기지 않습니다. 발송 실패는 성공적 전달로 주장하지 않고 공통 접수 응답과 비식별 서버 이벤트로 처리합니다. 이전 유효 링크는 발송 실패 시 유지합니다.
- local 프로필은 Git에서 제외한 파일 수신함만 사용합니다. prod에서는 file/disabled 모드를 금지하고 메일 키·발신자·HTTPS 링크 Origin을 요구합니다.
- 브라우저 인증은 HttpOnly/SameSite=Lax 쿠키, 운영 HTTPS에서 Secure입니다. JWT는 브라우저 JSON/localStorage에 전달하지 않습니다. DB 세션 확인으로 로그아웃 재사용을 차단합니다.
- 정확한 Origin/전용 헤더로 브라우저 쓰기를 제한하며 Java는 Bearer만 수락합니다. 운영 프록시 비밀값, 32KiB 본문 제한, 계정별 로그인 제한, 게시판 이메일 비공개, 운영 Swagger/상세 오류 비공개를 유지합니다.
- 신규 비밀번호는 BCrypt 바이트 한도 내 ASCII 12~64자, 닉네임은 2~40자입니다. 운영 DB는 TLS 검증, Flyway, Hibernate validate를 사용합니다. V2 마이그레이션은 기존 세션을 종료합니다.

## 검증 범위

백엔드 테스트 43개 성공(실패/오류/건너뜀 0), 프론트 lint/build 성공, 로컬 HTTP 계정 수명주기 smoke 성공. 브라우저에서 가입·인증 링크·재설정 요청·계정 관리 화면을 확인했습니다.

- 이메일 인증/정규화/중복 접수, 미인증 계정 거부, 닉네임·비밀번호 제한, 만료/잘못된 용도/재사용/동시 소비, 재발송 제한, 제공업체 실패 후 기존 링크 유지.
- 재설정 후 모든 기기 세션 거부·기존 비밀번호 거부·새 비밀번호 로그인, 탈퇴 비밀번호/확인 문구, 다른 회원 데이터 유지, 탈퇴 후 세션 무효화.
- Brevo 요청 주소/인증 헤더/JSON 본문/타임아웃과 원본 오류 비노출은 모의 HTTP 클라이언트로 검증합니다. 실제 Brevo 서버에는 보내지 않습니다.
- Flyway V1~V4/Hibernate 스키마 일치는 로컬 H2 MySQL 모드로 검증합니다. 실제 MySQL 마이그레이션·Docker 실행 및 CI도 통과했습니다.
- `scripts/smoke-auth.mjs`는 localhost 전용이며 파일 수신함에서 테스트 링크를 읽어 프록시·쿠키·실제 DB를 포함한 인증→재설정→탈퇴를 검증합니다. 자신이 만든 테스트 계정/콘텐츠만 삭제합니다.
- 서울시 121개 공식 거점 조회와 선택·화면 기반 실제 수집·원본 관측 시각·중복 방지·재시작 유지·지연 집계 보정도 확인했습니다.
- 2026-10-18 의존성 감사에서 프론트 운영 취약점 0건, Java 런타임 149개 중 영향 패키지 0개였습니다. 이번 계정 기능은 새 외부 라이브러리를 추가하지 않았습니다. 공개 배포 시 감사를 다시 실행합니다.

## 운영 확인과 남은 항목

키 교체·폐기와 이력 정리, 배포, 실제 인증·재설정 메일, 로그아웃·탈퇴, 새 로그인 시 기존 세션 차단을 확인했다. 동시 로그인은 사용자 행 잠금으로 직렬화하며 유효 세션 하나를 유지한다. 실패한 로그인은 기존 세션에 영향을 주지 않는다.

개인정보 안내 확정·게시, 별도 DB에서 백업 복구 시험, 모바일 화면 확인은 남아 있다. 상세 기록은 [운영 안내](manual-launch-guide.md)를 따른다.

## 한계와 운영 과제

- 공개 API의 접수 본문은 통일했지만 동기 메일 호출/DB 작업 시간 차이까지 완전히 숨기지는 않습니다. 메일 발송은 DB 트랜잭션과 원자적이지 않아 전달 후 커밋 실패 시 링크가 동작하지 않을 수 있습니다. 재요청으로 복구하며 규모가 커지면 암호화된 outbox와 비동기 작업을 도입합니다.
- 요청 제한은 메모리 기반 단일 인스턴스 기준이며 재시작 시 초기화됩니다. 메일 제공업체의 일일 발송 한도는 별도입니다. 다중 인스턴스는 공유 제한/예약 수집 잠금이 필요합니다. 가입 스팸에 대한 CAPTCHA/WAF는 아직 없습니다.
- MFA/OAuth/로그인 세션 목록은 미구현입니다. 엄격한 script nonce CSP도 추가 과제입니다.
- 탈퇴는 활성 앱 DB에 즉시 반영됩니다. 로컬 개발 수신함, 메일 제공업체 전송 로그, 호스팅 백업은 별도 저장소입니다. 사용자 안내와 실제 보존/삭제 정책을 맞춰야 합니다.
- 인증되지 않은 가입 대기 계정은 자동 삭제하지 않습니다. 공개 사용자 수가 늘면 대기 계정 보존 기간과 정리 작업이 필요합니다.
- 서버 휴면 중 수집과 만료 토큰 정리 작업도 멈추지만, 토큰 사용 시 만료 시각을 항상 확인하므로 휴면이 만료 링크를 유효하게 만들지는 않습니다.
- 서울시 공식 HTTP API 구간의 전송 제약은 남아 있습니다. 원문 URL에는 키가 있으므로 로그/공개 이슈에 남기지 않습니다.

설계 참고: [OWASP 비밀번호 복구](https://cheatsheetseries.owasp.org/cheatsheets/Forgot_Password_Cheat_Sheet.html), [Brevo HTTPS API](https://developers.brevo.com/docs/send-a-transactional-email), [Spring CSRF](https://docs.spring.io/spring-security/reference/servlet/exploits/csrf.html).

## 최종 점검에서 보완한 항목

- Render 템플릿에 Brevo 키·발신자·메일 모드·공개 Origin을 추가해 설정 누락을 줄였다.
- 운영 JWT/프록시 키 재사용 및 수집 활성화 상태의 서울시 키 누락은 시작 시 거부한다. 회귀 테스트 포함.
- 대시보드 비활성 탭에서는 5초 DB 조회를 중단하고 다시 보일 때 재개한다. 비활성 탭을 통한 서버 불필요 호출을 줄인다.
- 계정 smoke는 파일 메일 확인 플래그 없이는 시작하지 않는다. 별도 8081/3001 포트와 메모리 DB에서 실제 HTTP로 통과했다. 본인 계정 DB와 Brevo를 사용하지 않았다.
- 최종 배포 절차 및 공개 전 남은 확인은 manual-launch-guide.md 참조. 실제 MySQL·컨테이너 실행과 운영 HTTPS 연결은 확인했다. 백업 복구 시험은 남아 있다.
